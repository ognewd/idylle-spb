# Что такое Baseline миграций Prisma?

## Простое объяснение

**Baseline (базовая точка)** — это способ сказать Prisma: "Эта миграция уже применена к базе данных, не пытайся применять её снова".

## Проблема, которую решает baseline

### Ситуация без baseline:

1. У вас есть **существующая база данных** (продакшн) с таблицами и данными
2. Вы создаёте **миграцию** (например, `20250120000000_add_review_is_approved`)
3. Prisma пытается применить миграцию через `migrate deploy`
4. ❌ **Ошибка P3005**: "База данных не пустая, я не знаю, какие миграции уже применены"

### Почему это происходит?

Prisma хранит историю применённых миграций в специальной таблице `_prisma_migrations`. 
Если эта таблица пустая или не синхронизирована, Prisma не знает, что делать с существующей БД.

## Решение: Baseline

Baseline — это способ **синхронизировать** историю миграций с реальным состоянием базы данных.

### Как это работает:

```
1. У вас есть БД с таблицами (users, products, reviews и т.д.)
2. У вас есть миграция 20250120000000_add_review_is_approved
3. Эта миграция УЖЕ применена к БД (через db push)
4. Но Prisma не знает об этом в таблице _prisma_migrations

→ Baseline говорит Prisma: "Эта миграция уже применена, отметь её как выполненную"
```

## Как сделать baseline в вашем случае

### Вариант 1: Если миграция уже применена (ваш случай)

```bash
# На сервере
cd /root/idylle-spb
npx prisma migrate resolve --applied 20250120000000_add_review_is_approved
```

Эта команда:
- ✅ Добавляет запись в `_prisma_migrations`: "миграция 20250120000000 уже применена"
- ✅ Не выполняет SQL из миграции (он уже выполнен)
- ✅ Позволяет `migrate deploy` работать в будущем

### Вариант 2: Создать baseline для всей существующей БД

Если у вас много миграций, которые уже применены:

```bash
# 1. Создать начальную миграцию, отражающую текущее состояние
npx prisma migrate diff \
  --from-empty \
  --to-schema-datamodel prisma/schema.prisma \
  --script > prisma/migrations/0_init/migration.sql

# 2. Отметить её как применённую
npx prisma migrate resolve --applied 0_init

# 3. Отметить все остальные миграции как применённые
npx prisma migrate resolve --applied 20250120000000_add_review_is_approved
```

## Что происходит после baseline?

### До baseline:
```bash
$ npx prisma migrate deploy
❌ Error: P3005 - The database schema is not empty
→ Используется db push (менее безопасно)
```

### После baseline:
```bash
$ npx prisma migrate deploy
✅ Applied migration: 20250120000000_add_review_is_approved
✅ Database is up to date
→ Миграции работают правильно
```

## Преимущества baseline

1. ✅ **Безопасность**: `migrate deploy` вместо `db push`
2. ✅ **История**: Prisma знает, какие миграции применены
3. ✅ **Откат**: Можно откатывать миграции (если нужно)
4. ✅ **Синхронизация**: История миграций совпадает с реальным состоянием БД

## Риски baseline

1. ⚠️ **Однократность**: Baseline нельзя "отменить"
2. ⚠️ **Точность**: Нужно убедиться, что миграция действительно применена
3. ⚠️ **Расхождения**: Если схема БД не совпадает с `schema.prisma`, могут быть проблемы

## Рекомендация для вашего проекта

**Сделать baseline сейчас:**

```bash
# На сервере (SSH)
cd /root/idylle-spb
npx prisma migrate resolve --applied 20250120000000_add_review_is_approved
```

**Почему это безопасно:**
- ✅ Миграция уже применена через `db push`
- ✅ Структура БД соответствует миграции
- ✅ Это просто отметка в таблице `_prisma_migrations`
- ✅ Не изменяет данные или структуру БД

**После baseline:**
- ✅ `migrate deploy` будет работать
- ✅ Скрипт деплоя будет использовать `migrate deploy` вместо `db push`
- ✅ Более безопасное управление миграциями

## Проверка после baseline

```bash
# Проверить, что миграция отмечена как применённая
npx prisma migrate status

# Должно показать:
# ✅ 20250120000000_add_review_is_approved    Applied
```
