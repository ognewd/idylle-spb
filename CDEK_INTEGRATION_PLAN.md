# План интеграции СДЕК API

## Обзор

Интеграция службы доставки СДЕК в проект idylle-spb. Пользователь сможет выбирать между:
- **Самовывозом** (из магазина)
- **Доставкой СДЕК** (курьером или в ПВЗ)

При выборе доставки СДЕК подключается интеграция для расчета стоимости и создания заказа.

---

## Этапы интеграции

### Этап 1: Подготовка и настройка

#### 1.1 Получение учетных данных СДЕК
- [ ] Заключить договор с СДЕК на API-интеграцию (если еще не заключен)
- [ ] Получить из личного кабинета СДЕК:
  - `client_id` (Account ID)
  - `client_secret` (Secure Key)
  - Информацию о тестовом/боевом окружении

#### 1.2 Переменные окружения
Добавить в `.env.local` и `.env.production`:
```env
# СДЕК API
CDEK_CLIENT_ID=your_client_id
CDEK_CLIENT_SECRET=your_client_secret
CDEK_API_URL=https://api.cdek.ru/v2  # Боевой
CDEK_API_TEST_URL=https://api.edu.cdek.ru/v2  # Тестовый
CDEK_TEST_MODE=true  # Переключение между тестом/боем
```

### Этап 2: Базовые модули

#### 2.1 Авторизация СДЕК (`src/lib/cdek/auth.ts`)
Функционал:
- Получение OAuth2 токена через `/v2/oauth/token`
- Кэширование токена (срок жизни обычно 1 час)
- Автоматическое обновление при истечении
- Обработка ошибок авторизации

API метод:
```
POST /v2/oauth/token?grant_type=client_credentials
Authorization: Basic base64(client_id:client_secret)
```

#### 2.2 Основной API клиент (`src/lib/cdek/client.ts`)
Обертка для работы с API СДЕК:
- Автоматическая подстановка токена в запросы
- Обработка ошибок и повторные запросы
- Типизация запросов/ответов
- Логирование запросов (в dev режиме)

### Этап 3: API методы СДЕК

#### 3.1 Расчет стоимости доставки (`src/lib/cdek/calculator.ts`)
**API:** `POST /v2/calculator/tarifflist`

Параметры:
- Откуда (город отправителя)
- Куда (город получателя или ПВЗ)
- Вес посылки
- Габариты (длина, ширина, высота)
- Тип доставки (до двери / ПВЗ)

Возвращает:
- Список доступных тарифов
- Стоимость и срок доставки для каждого тарифа

#### 3.2 Список ПВЗ (Пункты выдачи заказов) (`src/lib/cdek/pvz.ts`)
**API:** `GET /v2/deliverypoints`

Параметры:
- Город (по коду или названию)
- Фильтры (работает сейчас, принимает оплату и т.д.)

Возвращает:
- Список ПВЗ с координатами, адресами, режимом работы

#### 3.3 Создание заказа (`src/lib/cdek/orders.ts`)
**API:** `POST /v2/orders`

Параметры:
- Данные отправителя
- Данные получателя
- Список товаров (название, вес, стоимость, количество)
- Тариф
- Адрес доставки или код ПВЗ
- Дополнительные услуги

Возвращает:
- UUID заказа в СДЕК
- Номер заказа СДЕК
- Статус заказа

#### 3.4 Получение статуса заказа (`src/lib/cdek/orders.ts`)
**API:** `GET /v2/orders/{uuid}`

Используется для:
- Отслеживания статуса доставки
- Обновления статуса заказа в нашей БД

### Этап 4: Backend API endpoints

#### 4.1 Расчет стоимости доставки (`src/app/api/delivery/cdek/calculate/route.ts`)
**Метод:** `POST`

Принимает:
```json
{
  "fromCity": "Санкт-Петербург",
  "toCity": "Москва",
  "weight": 1500,
  "length": 20,
  "width": 15,
  "height": 10,
  "deliveryType": "door" | "pvz"
}
```

Возвращает:
```json
{
  "tariffs": [
    {
      "tariff_code": 139,
      "tariff_name": "Экспресс-лайт дверь-дверь",
      "delivery_sum": 500,
      "period_min": 2,
      "period_max": 3
    }
  ]
}
```

#### 4.2 Список ПВЗ (`src/app/api/delivery/cdek/pvz/route.ts`)
**Метод:** `GET`

Параметры: `?city=Москва`

Возвращает список ПВЗ с координатами и адресами.

#### 4.3 Создание заказа СДЕК (`src/app/api/delivery/cdek/order/route.ts`)
**Метод:** `POST`

Вызывается при оформлении заказа, если выбран способ доставки "СДЕК".

### Этап 5: Обновление базы данных

#### 5.1 Модификация модели Order (`prisma/schema.prisma`)

Добавить поля:
```prisma
model Order {
  // ... существующие поля ...
  
  // СДЕК поля
  cdekOrderUuid        String?   // UUID заказа в системе СДЕК
  cdekOrderNumber      String?   // Номер заказа СДЕК
  cdekTariffCode       Int?      // Код тарифа (139, 138 и т.д.)
  cdekTariffName       String?   // Название тарифа
  cdekDeliveryType     String?   // "door" | "pvz"
  cdekPvzCode          String?   // Код ПВЗ (если выбрана доставка в ПВЗ)
  cdekPvzAddress       String?   // Адрес ПВЗ
  cdekDeliveryCost     Decimal?  @db.Decimal(10, 2) // Стоимость доставки
  cdekDeliveryDateMin  DateTime? // Минимальная дата доставки
  cdekDeliveryDateMax  DateTime? // Максимальная дата доставки
  cdekStatus           String?   // Статус в системе СДЕК
  cdekStatusUpdatedAt  DateTime? // Когда последний раз обновлялся статус
}
```

Миграция:
```bash
npx prisma db push
# или
npx prisma migrate dev --name add_cdek_fields
```

### Этап 7: Создание заказа

#### 7.1 Обновление `src/app/api/orders/route.ts`

Логика:
1. Если `deliveryMethod === 'cdek'`:
   - Вызвать API создания заказа в СДЕК
   - Сохранить `cdekOrderUuid`, `cdekOrderNumber` и другие поля в БД
   - Если ошибка - вернуть понятное сообщение пользователю

2. Если `deliveryMethod === 'pickup'`:
   - Оставить текущую логику (без изменений)

#### 7.2 Обработка ответа СДЕК
- Обработка успешного создания заказа
- Обработка ошибок (валидация, недоступность тарифа и т.д.)
- Логирование для отладки

## Основные тарифы СДЕК

| Код | Название | Описание |
|-----|----------|----------|
| 136 | Посылка склад-склад | Доставка между ПВЗ |
| 137 | Посылка склад-дверь | Из ПВЗ до двери получателя |
| 138 | Посылка дверь-склад | От двери отправителя до ПВЗ |
| 139 | Посылка дверь-дверь | От двери до двери |
| 233 | Экономичная посылка склад-склад | Экономный вариант |
| 234 | Экономичная посылка склад-дверь | Экономный вариант |

## Основные этапы работы пользователя

1. **Выбор товаров** → добавление в корзину
2. **Оформление заказа:**
   - Заполнение контактных данных
   - **Выбор способа доставки:**
     - Если "Самовывоз" → переход к оплате
     - Если "Доставка СДЕК":
       - Выбор города получателя
       - Выбор типа: "До двери" или "В ПВЗ"
       - Если "В ПВЗ" → выбор пункта выдачи
       - Если "До двери" → ввод адреса
       - Автоматический расчет стоимости и срока
       - Выбор тарифа (если предложено несколько)
3. **Выбор способа оплаты**
4. **Подтверждение заказа**
5. **Создание заказа в нашей БД + СДЕК**
6. **Отслеживание заказа**

## Важные моменты

### Ошибки и валидация
- Всегда проверять доступность тарифа в выбранном городе
- Обрабатывать случаи, когда нет доступных ПВЗ
- Валидировать вес и габариты перед расчетом
- Проверять корректность адреса для доставки до двери

### Производительность
- Кэшировать списки ПВЗ по городам
- Кэшировать расчеты стоимости (с учетом веса/габаритов)
- Использовать debounce для автокомплита городов

### Безопасность
- Не хранить `client_secret` в клиентском коде
- Все запросы к СДЕК делать через backend API
- Валидировать входные данные на сервере
- Обрабатывать ошибки без утечки чувствительных данных
