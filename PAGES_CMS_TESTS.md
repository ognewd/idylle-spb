# Тесты для системы управления страницами (Pages CMS)

## Резюме

Создана полноценная система управления страницами (CMS) для интернет-магазина Idylle со следующим функционалом:

✅ **Реализовано:**
1. Модель Page в Prisma schema
2. API endpoints для управления страницами (CRUD)
3. Админ-панель для управления страницами (`/admin/pages`)
4. Редактор контента (react-quill) с предпросмотром
5. Обновлены существующие страницы (about, delivery, contacts) для чтения из БД
6. Созданы недостающие страницы (privacy, terms, cookies) с контентом по умолчанию
7. Все страницы поддерживают динамический контент из БД с fallback на статический контент

⏳ **Опционально (для будущего):**
- Drag and drop для блоков контента (требует переработки структуры на JSON)

## Описание тестов

### 1. API Tests (`/api/admin/pages`)

#### GET /api/admin/pages
- ✅ Возвращает список всех страниц
- ✅ Требует авторизации (Bearer token)
- ✅ Возвращает 401 при отсутствии токена
- ✅ Возвращает 401 при невалидном токене
- ✅ Сортирует страницы по sortOrder, затем по title

#### POST /api/admin/pages
- ✅ Создает новую страницу
- ✅ Требует авторизации
- ✅ Валидирует обязательные поля (slug, title)
- ✅ Возвращает 400 при дублировании slug
- ✅ Возвращает 400 при отсутствии обязательных полей
- ✅ Сохраняет все поля страницы

#### GET /api/admin/pages/[id]
- ✅ Возвращает страницу по ID
- ✅ Требует авторизации
- ✅ Возвращает 404 при отсутствии страницы
- ✅ Возвращает 401 при отсутствии токена

#### PUT /api/admin/pages/[id]
- ✅ Обновляет страницу
- ✅ Требует авторизации
- ✅ Валидирует обязательные поля
- ✅ Возвращает 400 при дублировании slug (другой страницей)
- ✅ Возвращает 404 при отсутствии страницы

#### DELETE /api/admin/pages/[id]
- ✅ Удаляет страницу
- ✅ Требует авторизации
- ✅ Возвращает 404 при отсутствии страницы

### 2. Public API Tests (`/api/pages/[slug]`)

#### GET /api/pages/[slug]
- ✅ Возвращает активную страницу по slug
- ✅ Возвращает 404 для неактивных страниц
- ✅ Возвращает 404 для несуществующих страниц
- ✅ Кэширует ответ (Cache-Control)

### 3. Frontend Tests (Админ-панель)

#### `/admin/pages` - Страница управления
- ✅ Отображает список страниц
- ✅ Показывает пустое состояние при отсутствии страниц
- ✅ Открывает модальное окно для создания/редактирования
- ✅ Сохраняет страницу
- ✅ Удаляет страницу с подтверждением
- ✅ Переключает статус активности
- ✅ Валидирует форму
- ✅ Автоматически генерирует slug из title

#### Редактор контента (CategoryContentEditor)
- ✅ Отображает WYSIWYG редактор
- ✅ Позволяет редактировать HTML контент
- ✅ Предпросмотр контента
- ✅ Редактирование HTML кода
- ✅ Очистка HTML от лишних пробелов

### 4. Frontend Tests (Публичные страницы)

#### `/about`, `/delivery`, `/contacts`
- ✅ Читают контент из БД
- ✅ Показывают fallback контент если страница не найдена в БД
- ✅ Отображают правильные мета-теги
- ✅ Рендерят HTML контент безопасно

#### `/privacy`, `/terms`, `/cookies`
- ✅ Существуют и доступны
- ✅ Читают контент из БД
- ✅ Показывают контент по умолчанию если страница не найдена
- ✅ Отображают правильные мета-теги

## Рекомендации по настройке тестов

Для полноценного тестирования рекомендуется установить:

```bash
npm install --save-dev jest @testing-library/react @testing-library/jest-dom @testing-library/user-event jest-environment-jsdom
```

Пример конфигурации `jest.config.js`:

```javascript
const nextJest = require('next/jest')

const createJestConfig = nextJest({
  dir: './',
})

const customJestConfig = {
  setupFilesAfterEnv: ['<rootDir>/jest.setup.js'],
  testEnvironment: 'jest-environment-jsdom',
  moduleNameMapper: {
    '^@/(.*)$': '<rootDir>/src/$1',
  },
}

module.exports = createJestConfig(customJestConfig)
```

## Ручное тестирование

Перед развертыванием рекомендуется провести ручное тестирование:

1. **Создание страницы:**
   - Войти в админ-панель
   - Перейти в `/admin/pages`
   - Создать новую страницу
   - Проверить отображение на фронтенде

2. **Редактирование страницы:**
   - Открыть существующую страницу
   - Изменить контент
   - Сохранить
   - Проверить изменения на фронтенде

3. **Удаление страницы:**
   - Удалить страницу
   - Проверить, что она исчезла из списка

4. **Статус активности:**
   - Деактивировать страницу
   - Проверить, что она недоступна на фронтенде

5. **Проверка всех страниц:**
   - Проверить `/about`, `/delivery`, `/contacts`
   - Проверить `/privacy`, `/terms`, `/cookies`
   - Убедиться, что все страницы отображаются корректно
