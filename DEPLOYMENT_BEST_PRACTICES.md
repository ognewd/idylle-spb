# 🔒 Лучшие практики деплоя - как избежать проблем

## Проблемы, которые возникли

1. **Таблица `pages` не была создана**
   - Причина: миграция Prisma не применилась (возможно, из-за неправильного DATABASE_URL или ошибки)
   - Решение: добавить `export DATABASE_URL` в workflow перед миграциями

2. **Папка `.next` отсутствовала**
   - Причина: сборка не выполнилась или была удалена
   - Решение: добавить проверку после сборки

## Улучшения в workflow

### ✅ Что было исправлено:

1. **Явное указание DATABASE_URL** в workflow перед миграциями
2. **Проверка успешности сборки** - если `.next` не создана, деплой останавливается
3. **Логирование этапов** - каждый шаг теперь выводит сообщение
4. **Проверка логов** после запуска - автоматическая проверка на ошибки

### 📋 Правильный порядок операций:

1. ✅ Получить код из Git
2. ✅ Установить зависимости (`npm install`)
3. ✅ **Применить миграции Prisma** (до сборки!)
4. ✅ Сгенерировать Prisma Client
5. ✅ Создать начальные данные (seed scripts)
6. ✅ Очистить старые build файлы
7. ✅ **Собрать приложение** (`npm run build`)
8. ✅ **Проверить, что сборка прошла** (папка `.next` существует)
9. ✅ Перезапустить приложение (PM2)
10. ✅ Проверить логи

## Почему порядок важен

- **Миграции до сборки**: TypeScript компиляция использует Prisma Client, который должен быть сгенерирован с актуальной схемой
- **Сборка обязательна**: Next.js требует папку `.next` для работы в production
- **Проверки**: лучше узнать о проблеме сразу, а не через пользователей

## Дополнительные рекомендации

### 1. Всегда проверяйте миграции локально перед деплоем

```bash
# Локально
npx prisma db push
npx prisma generate
npm run build
```

### 2. Используйте миграции вместо `db push` для продакшена

В будущем можно перейти на миграции:
```bash
npx prisma migrate dev  # локально
npx prisma migrate deploy  # на продакшене
```

### 3. Добавьте health check endpoint

Уже есть `/api/health` - можно использовать для проверки после деплоя.

### 4. Настройте мониторинг

- PM2 monitoring
- Uptime monitoring (например, UptimeRobot)
- Error tracking (например, Sentry)

## Что делать при проблемах

1. **Проверить логи PM2**: `pm2 logs idylle-spb --lines 50`
2. **Проверить статус**: `pm2 status`
3. **Проверить базу данных**: подключиться и проверить структуру
4. **Проверить сборку**: существует ли папка `.next`
5. **Проверить переменные окружения**: `pm2 env 0`

## Автоматизация

Текущий workflow теперь включает все необходимые проверки. При следующем деплое:
- Миграции применятся автоматически
- Сборка будет проверена
- Приложение перезапустится с правильными переменными
