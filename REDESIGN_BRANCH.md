# Ветка для редизайна

Ветка **`redesign`** — отдельная копия сайта для «примерки» нового дизайна.  
Та же БД (`idylle_spb_dev` из `.env.local`), другой код — можно спокойно менять вёрстку и компоненты.

## Правила

- **Не мержить** `redesign` в `main`.
- **Не пушить** в `main` и не деплоить на прод из этой ветки.
- В прод и в основной dev идёт только код из `main`.

## Как работать локально

### Один сайт (только редизайн)

```bash
git checkout redesign
npm run dev
```

Сайт откроется на http://localhost:3000 (или следующем свободному порту).

### Два сайта сразу: основной dev + редизайн

Одна и та же БД, два процесса:

**Терминал 1 — основной сайт (main):**
```bash
git checkout main
npm run dev
# Откроется на http://localhost:3000
```

**Терминал 2 — редизайн:**
```bash
git checkout redesign
npm run dev -- -p 3005
# Откроется на http://localhost:3005
```

Оба используют `DATABASE_URL` из `.env.local` → одна база, разные версии интерфейса.

### Сохранять изменения только в ветке редизайна

```bash
git checkout redesign
# правки по дизайну...
git add .
git commit -m "Редизайн: ..."
git push origin redesign   # опционально: бэкап ветки на GitHub, main не трогаем
```

Когда редизайн будет готов к проду — тогда делаете merge `redesign` → `main` и деплой как обычно.
