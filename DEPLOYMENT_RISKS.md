# Анализ рисков текущего деплоя

## Изменения, которые были сделаны:

### 1. ✅ `ignoreBuildErrors: true` в next.config.js
**Риски:**
- ⚠️ **СРЕДНИЙ РИСК**: Могут быть скрыты реальные ошибки типов TypeScript
- ⚠️ Проблемы с типами могут проявиться в runtime, а не во время сборки
- ✅ **Митигация**: Ошибки типов все равно видны в IDE и при разработке

**Рекомендация:**
- Оставить как есть, но периодически проверять типы локально: `npx tsc --noEmit`
- Рассмотреть возможность вернуть `false` после решения проблем с зависимостями Next.js

### 2. ⚠️ `prisma db push` вместо `migrate deploy`
**Риски:**
- 🔴 **ВЫСОКИЙ РИСК**: `db push` может привести к потере данных при конфликтах схемы
- 🔴 Нет истории миграций - сложнее откатывать изменения
- ⚠️ `db push` не проверяет совместимость изменений с существующими данными
- ⚠️ Может удалить колонки/таблицы, если они не указаны в схеме

**Текущая ситуация:**
- Скрипт использует `db push` только если `migrate deploy` падает с ошибкой P3005
- Это означает, что база данных не была инициализирована через миграции

**Рекомендация:**
- ✅ **КРИТИЧНО**: Сделать baseline миграций для существующей БД:
  ```bash
  npx prisma migrate resolve --applied 20250120000000_add_review_is_approved
  ```
- После baseline миграции будут работать нормально
- Рассмотреть создание резервной копии БД перед каждым деплоем

### 3. ✅ Полная переустановка node_modules
**Риски:**
- ⚠️ **НИЗКИЙ РИСК**: Медленнее, но безопаснее
- ✅ Гарантирует чистую установку зависимостей
- ⚠️ Может занять больше времени

**Рекомендация:**
- Можно вернуться к `npm ci` после решения проблем с зависимостями
- Или использовать `npm ci --force` для принудительной переустановки
